# REVIEW.md

Review of the starter `app/main.py`, numbered in the order I found the defects: first those I hit while exercising the
running starter with the sample data, then those found by reading the code against `openapi.yaml` and `DATA_MODEL.md`.
Line numbers refer to the original starter. "Observed" means I reproduced it; "Expected" means the input and the wrong
result derived from the code and the contract.

## Checked and not a defect

- **`load_dotenv()`**: the default `override=False` means real environment variables take priority over `.env`, as required.
- **Synchronous `def` endpoints with PyMongo**: FastAPI runs them in a thread pool, and `MongoClient` is thread-safe with a connection pool. Concurrency correctness comes from unique indexes and atomic updates, not from the endpoint style.
- **`IST = timezone(timedelta(hours=5, minutes=30))`**: correct. India has no daylight saving time, so a fixed offset is exact.
- **`doc.pop("_id")` after `insert_one`**: needed in the starter because `insert_one` adds `_id` to the dict passed in. It is no longer needed once responses are built by `record_out` / `employee_out`.
- **Storing `date` and `joined_on` as `YYYY-MM-DD` strings and comparing them with `$gte` / `$lte`**: correct. That format sorts lexically in date order.
